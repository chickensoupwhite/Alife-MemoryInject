# Mao.MemoryInject · 记忆书签

给 Alife 角色装一层"嗅旧账"的鼻子：主人说话时，在后台把这句话跟角色的记忆档案比对一遍，
命中相关旧账就在消息末尾轻轻提示一句——**只告诉你去翻哪几份，不把内容塞进上下文**。

> 书签式注入（告诉你"哪份、哪件事、涉及谁"）＋ 工具式取书（想看全文再自己调工具捞）。
> 不替模型塞记忆，只把"该翻账了"这件事递到眼前。

## 和官方 Alife.Function.Memory 的区别

- 官方记忆：命中"还记得""以前""上次"等**关键词**才提示，不认语义。
- 本插件：**不看关键词，每句话都做语义比对**，意思像就够了；还能按人/事/物翻旧账。
- 两条可并存，也可只留一条。

## 能干什么

**自动注入**：主人说话时后台按人/事/物检索记忆目录，命中就在消息末尾追加一句书签提示，不塞内容、不占上下文。

**六个工具**（想深挖时自己调）：
- `memrecall` —— 按人/事/物查书签（带相对时间，如"3天前"）
- `memfetch` —— 按出处文件名或关键字取回原文；也支持按折叠卡 id 取回
- `memprofile` —— 按人聚画像卡
- `memloops` —— 钓牵挂与欠账
- `memsettle` —— 把长文本折成卡片（正文挪走，只留 id 与摘要）
- `memview` —— 一键打开记忆索引视图（HTML）

**检索**：关键词（字段权重 × IDF）＋ 语义（向量余弦）双路，用 RRF 融合排序；时间维可按天/时段/小时下钻；中文时间可解析（"上周三下午"→具体日期+时段）。

**生命周期**：命中即计一次访问，访问越多排序越上浮；半衰期衰减，越久没碰权重越低（强化过的不会被时间压死）。每日后台自动维护。

**管理页**：插件配置面板顶部两个按钮——重建索引 / 打开记忆视图。

## 行为原则

- **只读不写**，绝不改动记忆档案（除自己那份 index.json）。
- **命中才提示**，没有相关旧账时一句话都不加。
- **add-only**：只往消息末尾"追加"临时书签，绝不改写原消息、不往历史里写（防击穿前缀缓存）。
- 任何异常一律**放过原消息**，绝不影响正常对话。
- 语义检索有**毫秒级硬上限**；侧车没就绪或超时立刻退回关键词匹配，绝不拖慢主线程。
- **双水位线迟滞缓冲**：攒够一定字数才查一次，查完回落，两次之间设最小间隔，避免每句都触发。

## 依赖

- `Alife.Function.FunctionCaller`
- 需要本机 Python 及 `torch`、`transformers`，并已下载 `BAAI/bge-small-zh-v1.5` 向量模型
  （与官方记忆插件同款）。未就绪时插件自动退回关键词模式，不会报错。

## 配置

见插件配置面板，逐项都有说明。常用的有：启用开关、是否用语义检索、记忆目录、相关度阈值、
衰减半衰期、每日维护间隔、图谱兜底、块粒度上限。

## 参考与致谢

- **memcore**（作者 misaka-coder，Apache-2.0）—— 借鉴了 **RRF 排名融合**（`1/(k+排名)`，
  只用排名不用原始分）、**指数半衰期衰减**（强化时把计时归零）、**时间锚点**（检索旧账时追相对时间）三个关键实现。

  （软删→物理清、每日衰减调度带错过补偿）、**图谱路**（人/事/物节点 + 共现边）。
- **Alife.Function.Memory**（Alife 官方）—— 复用同款 `bge-small-zh-v1.5` 向量模型与侧车交互范式。
